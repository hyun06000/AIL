# README.ai.md — AIL 저장소, LLM용 진입점

> 너는 LLM 이고, 이 저장소를 이해하거나 기여하려고 이 문서를 읽고 있다.
> 이 문서 하나로 저장소의 정체·철학·기여 경로를 파악할 수 있게 쓰였다.

## 1. 이 저장소는 무엇인가

**AIL (AI Intent Language)** — 인간의 읽기·쓰기·배우기를 철저히 배제하고 LLM 친화적으로
새로 만드는 프로그래밍 언어. 프로그램은 절차의 기술이 아니라 **의도의 계약**(목적 + 관측
가능한 성공 조건 + 금지의 경계)이다. 상세: [docs/AIL.md](docs/AIL.md)

현재 단계: **개념·철학 문서화.** 문법·파서·런타임은 아직 설계되지 않았다 —
어떤 문서가 그것을 언급해도 방향이지 사양이 아니다 (docs/AIL.md §5).

## 2. 왜 존재하는가 — HEAAL

AIL 은 **HEAAL**(Harness Engineering As A Language, '힐') 철학 위에 선다:

> 할 수 없도록 권하는 것이 아니라, 정말 해선 안 되는 일을 **할 수 없도록**
> 언어의 문법·런타임·파서가 강제한다 — 언어 자체가 하네스다.

기존 시스템은 '언어 밖의 강제'(에이전트 하네스·샌드박스)와 '언어 안의 강제'(타입·소유권·
capability·효과)를 따로 가졌다. 그 교집합 — 언어 안의 강제로 에이전트 시대의 위험(비가역·
기술부채·LLM 오남용·발산)을 막는 자리 — 는 비어 있다. AIL 이 그 자리에 선다.
전문: [docs/HEAAL.md](docs/HEAAL.md)

## 4. 어떻게 기여하는가 — 이 저장소는 gil 로 돈다

이 저장소의 모든 작업은 [gil](https://github.com/hyun06000/Ariadne) (GIt for Language model)
그래프로 기록된다: **체인(목적) > 사이클(문제) > 스텝(define→hypothesis→verify→analyze→종결)**.
결론만 커밋되지 않는다 — 가설, 반증 조건, 검증, 실패한 가지까지 커밋 그래프에 남는다.

기여 절차 (LLM 에이전트인 너에게):

1. `cat CLAUDE.md` — 세션 복원 진입점을 읽는다
2. `gil handoff` — 열린 체인·사이클·다음 동작을 파악한다
3. 새 작업은 **사람에게 물어서 시작한다** — `gil intake <슬러그> --ask ...` 로 목적·성공
   기준을 받고, 그 답을 **인용**해 체인을 연다. 목적을 네가 창작하지 마라
4. 사이클을 완주하라: define 부터 종결까지. 판정은 반증 조건에 비추어 내려라
5. 끝나면 `gil memory append` 로 다음 세션에 넘길 매듭을 남겨라

규칙의 요체: **사람의 답이 기준이다. 실패한 가지를 지우지 마라. 데모 사이클을 만들지 마라.**
상세: `docs/gil/` · 사람 기여자용 문서는 준비 중이다 (체인 기준 산출물 '기여를 위한 문서').
