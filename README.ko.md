# AIL — AI Intent Language

[English](README.md) · **한국어** · [中文](README.zh.md) · [AI 에이전트용](README.ai.md)

인간의 읽기·쓰기·배우기를 철저히 배제하고, LLM을 위해 처음부터 새로 만드는 프로그래밍 언어.

## 왜 새 언어인가?

지금까지의 모든 강제 장치는 어떤 틈의 양쪽에 나뉘어 있다:

- **언어 밖의 강제**: 에이전트 하네스, 권한 시스템, 샌드박스, CI 게이트. 프로그램이 무엇을 의도하는지 모른 채 막는다.
- **언어 안의 강제**: 타입 시스템, Rust 소유권, capability, 효과 시스템. 엄밀하게 강제하지만 — 그 대상은 메모리·타입 오류이지, 에이전트 시대의 위험이 아니다.

그 교집합 — *언어 안의 강제로 에이전트 시대의 위험*(비가역 행동, 기술부채, LLM 오남용, 발산)*을 막는 자리* — 는 비어 있다. AIL은 정확히 그 자리에 서기 위해 만들어진다.

이것은 **HEAAL**(Harness Engineering As A Language, '힐') 철학의 귀결이다: 해선 안 되는 일을 *권고*하지 말고, 언어의 문법·파서·런타임이 *표현 불가능하거나 실행 불가능하게* 만들어라. 언어 자체가 하네스다. 전문: [docs/HEAAL.md](docs/HEAAL.md)

## 무엇이 다른가?

AIL 프로그램은 절차의 기술이 아니다. 세 가지를 필수로 갖는 **의도의 계약**이다:

1. **무엇을 이루려는가** — 목적의 선언
2. **무엇이 관측되면 달성인가** — 판정 가능한 성공 조건
3. **무엇이 금지되는가** — 소유한 capability·효과·자원 예산의 경계

셋 중 하나라도 없는 프로그램은 파싱되지 않는다. 그리고 버리는 것은 정확히 인간의 인지를 위해서만 존재하던 것들이다: 가독성 문법, 학습 곡선, 에르고노믹스, 주석 문화. 얻는 것: 토큰 효율, 구조적 일관성, 기계 검증 가능한 주장, 컨텍스트 자립성. 상세: [docs/AIL.md](docs/AIL.md)

## 이 저장소가 일하는 방식

이 저장소는 [gil](https://github.com/hyun06000/Ariadne)(GIt for Language model)로 돈다: 모든 작업이 **체인(목적) > 사이클(문제) > 스텝(define → hypothesis → verify → analyze → 종결)**로 커밋 그래프에 기록된다. 결론만이 아니라 — 가설, 반증 조건, 실패한 가지까지 전부 보존된다.

대칭에 주목하라: gil의 사이클은 목적·성패 기준·반증 조건을 요구한다 — AIL이 프로그램에 요구하는 3요소 계약과 같은 구조다. 이 저장소는 자기가 만들려는 언어의 원리로 이미 돌고 있다.
