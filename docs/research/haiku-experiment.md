# Haiku 실모델 실험 — 첫 판정: AIL 패배와 그 원인

> gil 사이클 `ail-grammar-skeleton/haiku-experiment`. 생성물·프롬프트·집계: `experiments/haiku/`.
> 설계(사람, 4차 인터뷰): 주 사용자 = Haiku. 언어 지정 외 프롬프트 동일. AIL만 스펙 카드 동봉.

## 0. 결과 (claude-haiku-4-5, 문제 3 × 언어 5)

| 언어 | 3문제 평균 토큰(5계열) | Python 대비 |
|---|---|---|
| **js** | 315 | **−9%** |
| python | 347 | 0% |
| **ail** | **391** | **+13%** ❌ |
| go | 501 | +45% |
| c | 914 | +164% |

- AIL 스펙 카드 입력 오버헤드: **평균 196토큰** (매 요청 고정비)
- 퓨샷 문법 준수: **3/3 문제에서 전 task가 goal·done·never 3슬롯 준수** — "퓨샷으로 바로 배운다"는 성립
- 반면 **경제성 가설은 반증됨**: 사람이 쓴 초안은 Python보다 −28%였지만, Haiku가 쓴 AIL은 +13%

문제별 전체 표는 `experiments/haiku/tally.py` 출력 참조.

## 1. 왜 졌는가 — 생성물이 가리키는 문법 구멍 3개

1. **반복 구문의 부재.** 카드에 `while` 금지만 있고 유한 반복 구문이 없다 → Haiku는 P2·P3에서 **꼬리 재귀로 우회**했고, 그러느라 태스크를 3~4개로 쪼갰다(각각 goal·done·never 3슬롯 의례를 지불). P2가 AIL 최악(+47%)인 이유의 대부분. **의례를 없애려던 언어가 의례를 곱하게 만들었다.**
2. **`again`의 의미 불명.** P1에서 Haiku는 `again 3 wait 2`를 선언 한 줄로 쓰지 못하고 **재시도를 4번 수동 언롤**했다(같은 블록 4벌). 카드가 `again <N> wait <M>`의 위치·의미(계약 수준 선언인지, 지점 재실행인지)를 정의하지 않았기 때문.
3. **`done` 키워드 충돌.** P3에서 `done`이 성공 조건 키워드이자 결과 필드명(`return { done stats.done }`)으로 쓰였다 — 가장 자연스러운 결과 이름과 키워드가 충돌한다. bareword 구조(원칙 6)와 1토큰 키워드(원칙 2)가 **예약어 충돌**이라는 새 제약을 낳는다.

## 2. 해석

- 지표를 가른 건 표기가 아니라 **모델이 문법의 빈 곳을 우회하는 비용**이다. 사람 초안 −28% vs Haiku +13%의 갭 41%p가 전부 구멍 1·2에서 나왔다.
- JS가 Python을 이긴 것(−9%)도 같은 원리다: async/await·try/catch가 이 문제군의 의례를 잘 흡수한다. **AIL의 경쟁 상대는 C가 아니라 JS다.**
- 긍정 신호: 3슬롯 준수 3/3 — 강제 구조 자체는 퓨샷으로 전달된다. 고칠 것은 철학이 아니라 카드의 구멍이다.

## 3. 다음 설계 (fail 잎이 물려주는 것)

1. 유한 반복 구문 추가 — `each x in xs { }` 류 (H4: 유한 컬렉션 위에서만)
2. `again`을 계약 수준 선언으로 명시: "task 본문 실패 시 N회 재실행, 간격 M" — 예시를 카드에 포함
3. 예약어 충돌 정책: 예약어의 bareword 키 사용 허용(문맥 분리) 또는 결과 관용 필드(ok 등)와 겹치지 않게 키워드 재선정
4. 수정 카드로 동일 실험 재실행 → Python·JS 재대결
