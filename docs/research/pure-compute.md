## 무엇이 격차를 만들었나

- **fn(순수 함수)**: 계약 슬롯 의례 제거 + 순수성의 문법 강제(효과 네임스페이스·uses가 fn 안에서 파싱 불가 — 슬롯 없이도 H1이 구조로 성립)
- **표현력 2건(사람 승인)**: `each x, i in xs` / `each i in range(n)` 인덱스 반복(P4 역전의 주역: 293→189), 식 위치 `if c { a } else { b }`(else 필수 — H2)

## P10 동률의 해부 (정직하게)

3표본 121·124·161 — 표본 분산(±20)이 JS와의 격차(1)보다 크다. 결론: **P10급 문자열 파싱 문제에서 AIL과 JS는 토큰 동급**. 남은 비용은 표기 아닌 표준 함수 어휘(split·문자열 처리)의 표현 차이로, 표준 라이브러리 설계(미래 체인)의 몫.
