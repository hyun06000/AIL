# 토큰 절약 전략 조사 — 케이브맨에서 문법까지

> gil 사이클 `ail-grammar-skeleton/abbrev-stats` 산출물. 사람의 요청: *"케이브맨 프로젝트 같은 토큰 전략들이 굉장히 많다. 장단점을 조사해도 좋을 것 같네."*
> 이 조사는 지식 기반 정리이며(실측 아님), AIL 문법 층과의 관계를 짚는 것이 목적이다.

## 0. 절약이 일어나는 층위

토큰 절약 전략은 어느 층에서 일하느냐로 갈린다: **프롬프트 층**(입력을 줄임) / **출력 스타일 층**(모델이 짧게 말하게 함) / **표기 층**(같은 내용을 싼 표기로) / **문법 층**(내용 자체를 덜 필요하게 — AIL의 자리).

## 1. 전략 6종 장단점

| 전략 | 층위 | 무엇을 하나 | 장점 | 단점 |
|---|---|---|---|---|
| **케이브맨 스타일** | 출력 스타일 | "원시인처럼 짧게 말해라" — 관사·조사·완곡어 제거한 전보체 출력 | 산문 출력 30~50% 절감, 설정 비용 0 | **권고다** — 컨텍스트 길어지면 풀림. 정밀도 손실(관계·조건이 생략됨). 코드 출력엔 거의 무효(코드는 이미 전보체) |
| **구조화 출력 강제** (JSON 스키마·함수 호출) | 출력 스타일+런타임 | 스키마 밖 출력을 런타임이 거부 | 산문 제거가 **강제됨**, 파싱 신뢰성 | 스키마 자체가 입력 토큰. JSON 표기세(따옴표·콜론 — [tokenizer-survey.md](tokenizer-survey.md) 원칙 6) |
| **컨텍스트 내 코드북** (약어 사전 합의) | 표기 | "이후 UP=userProfile로 표기" 식 사전 선언 | 대량 반복되는 긴 이름에서 이득 | 사전 자체가 토큰. 반복 임계치 밑이면 손해. 모델이 사전을 어기면 무효 — 권고 |
| **no-prose 지시** ("코드만, 설명 금지") | 출력 스타일 | 전후 설명·사과·요약 제거 | 코드 태스크에서 즉효, 큼 | 권고 — 모델·턴에 따라 샘. 디버깅 정보까지 같이 사라질 수 있음 |
| **프롬프트 압축** (LLMLingua류) | 프롬프트 | 작은 모델로 저정보 토큰 삭제 | 긴 컨텍스트에서 2~5× 압축 보고 | 별도 모델·파이프라인 비용. 손실 압축 — 무엇이 사라졌는지 보장 없음 |
| **추론 생략/제한** (CoT 억제, 사고 예산) | 출력 스타일 | 중간 추론을 안 쓰거나 상한 | 추론 토큰이 지배적인 태스크에서 큼 | 정답률과 직접 트레이드오프. 난이도에 따라 역효과 |

## 2. 공통 패턴 — 그리고 HEAAL의 진단

여섯 중 다섯이 **권고 층**에서 일한다(구조화 출력만 부분적 강제). 그래서 전부 같은 실패 모드를 공유한다: *컨텍스트가 길어지면 풀리고, 어겨져도 아무도 모른다.* 이것은 HEAAL.md §1의 권고/강제 구분 그대로다 — 토큰 절약도 안전과 같은 구조의 문제다.

또 하나: 이 전략들은 전부 **이미 비싼 표현을 사후에 깎는다.** 산문이 나오게 두고 줄이라 하고, 의례가 있는 언어로 쓰게 두고 압축한다.

## 3. AIL의 자리 — 문법 층 절약

AIL은 위 전략들과 경쟁하지 않는다. 층이 다르다:

1. **절약이 문법으로 강제된다.** 케이브맨·no-prose가 "짧게 말하라"고 비는 것을, AIL은 산문이 설 자리가 문법에 없는 것으로 만든다. 풀리지 않는다.
2. **의례가 애초에 없다.** 재시도·에러 전파·예산이 의도 계약 선언에 흡수되므로([tokenizer-survey.md](tokenizer-survey.md) 원칙 7, Python 105 vs C 220 실측), 사후 압축할 대상이 안 생긴다.
3. **코드북의 이득을 표기세 없이.** 코드북 전략의 이득(반복 패턴의 압축)은 AIL에서는 1토큰 실단어 키워드([abbrev-stats.md](abbrev-stats.md))로 언어 자체에 내장된다 — 사전 선언 비용도, 어길 가능성도 없다.

즉 기존 전략들의 교훈은 "절약을 권고에 맡기면 샌다"이고, AIL은 그 교훈의 문법 층 응답이다. 다만 상호 배타가 아니다 — AIL 위에서도 프롬프트 압축·추론 예산은 여전히 유효한 보완 층이다(H4의 예산 선언과 자연스럽게 결합).

## 4. 한계

- 본 조사는 실측이 아니라 정리다. 절감률 수치는 해당 전략들의 통상 보고 범위이고 우리 벤치가 아니다.
- "케이브맨 프로젝트"의 정식 출처·구현은 확인하지 못했다 — 사람이 가리킨 개념(전보체 출력 압축)으로 다뤘다. 구체 링크를 주면 보강한다.
