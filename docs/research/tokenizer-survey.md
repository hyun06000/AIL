# 토크나이저 실측 조사 — 문법 뼈대를 위한 원칙

> gil 체인 `ail-grammar-skeleton`, 사이클 `tokenizer-survey` 의 산출물.
> 재현: `python3 experiments/tokenizer/measure.py` (토크나이저 5개, 샘플 2군 — 스크립트에 전부 박제).
> 측정일 2026-08-03. 측정은 도구다 — 이 문서는 원칙을 만들지, 점수를 만들지 않는다 (LESSONS §5).

## 0. 무엇을 쟀나

- **토크나이저 5개**: o200k_base(GPT-4o계), cl100k_base(GPT-4계), Qwen2.5-Coder, DeepSeek-V3, Phi-3(Llama계 32k vocab — 구세대 대조군)
- **A군**: 동일 로직(HTTP fetch + JSON 파싱 + 재시도 + 에러 반환)을 Python/Go/C/JS로
- **B군**: 표기 변형 12종 — 키워드 길이 3단계, 식별자 스타일 3종, 블록 구분 3종, 연산자 2종, 구조 표기 2종

## 2. 토크나이저-불변 원칙 (실측 근거 병기)

1. **축약은 최악이다.** `usrProfRes`는 문자를 40% 줄이고도 **절대 토큰이 full-word보다 많다**(19~26 vs 14~19). 축약 키워드(`itt`,`gl`,`fbd`)도 동일하게 역전당했다(21~26 vs 19~24). 토크나이저의 어휘는 실제 영어 코퍼스에서 왔기 때문이다. → AIL 키워드·표준 식별자는 **온전한 영어 단어**로 한다. "짧게 쓰기"는 인간 에르고노믹스의 유물이고, LLM에겐 비용이다 — AIL.md §2의 실측 증거.
2. **키워드는 1토큰 단어를 고른다.** `intent`/`goal`/`forbid`(kw-mid)가 절대 토큰 최소. 더 긴 굴절형(`intention`,`achieves`,`forbidden`)은 +1~2. → 키워드 후보는 5계열 전부에서 1토큰인지 실측으로 검사해 채택한다 (검사 스크립트가 이미 있다).
3. **camelCase ≥ snake_case.** 모든 계열에서 camel이 같거나 싸다(최대 -7토큰, phi3). `_`가 병합을 끊는 계열이 있다. → 표준 식별자는 camelCase.
4. **블록은 중괄호.** brace(14~16) < indent(16~19) < `end`(19~21), 5계열 전부 동일 순위. `end` 류 닫는 키워드는 계열 불문 세금. → 블록 구분자는 `{ }`.
5. **연산자는 기호.** `>= && !` 조합이 5계열 **전부 정확히 12토큰** — 이 실험에서 유일하게 완전 불변인 표기. 단어 연산자는 문자가 27% 늘고 토큰도 같거나 많다. → 연산자는 관용 기호를 그대로.
6. **구조 표기는 따옴표·콜론 세금을 피한다.** S식이 JSON보다 전 계열에서 25~30% 싸다(24~31 vs 32~38). JSON의 비용은 `"key":` 마다 붙는 따옴표 2 + 콜론이다. → AIL의 의도 계약 표기는 키를 bareword로, 콜론 없이 위치·괄호로 구조를 만든다 (S식 그 자체일 필요는 없고, 이 원리를 갖는 커스텀 표기면 된다).
7. **토큰을 지배하는 건 표기가 아니라 의례다.** A군에서 같은 로직이 105~220토큰 — 2배 차이는 문법 밀도가 아니라 보일러플레이트에서 온다. → AIL이 "파이썬/go/c/js를 이기는" 길은 글자를 줄이는 게 아니라 **의례를 없애는 것**: 재시도·에러 전파·타임아웃 같은 패턴이 의도 계약의 선언 한 줄이 되면, H1~H4 강제가 곧 토큰 경제성이 된다.

## 3. 한계

- 샘플 규모가 작다(로직 1종 × 4언어, 변형 12종). 원칙 1~6은 효과가 크고 방향이 5계열 일관이라 뼈대 방향으론 충분하지만, 문법 확정 단계에서는 키워드 후보 전수를 스크립트로 재검한다.
- Llama 3(128k)·Gemma는 게이트라 미포함. Llama계는 구세대 32k(phi3)로 대체 — 최신 Llama 3 토크나이저가 들어오면 ρ가 최신 계열 쪽으로 붙을 것으로 추정(추정임).
- 레이턴시·퓨샷 학습성은 이 조사의 범위 밖 — 문법 뼈대가 선 뒤 별도 사이클.
